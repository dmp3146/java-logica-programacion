# Aplicaciones finales

Aquí ya no se trata de ejercicios aislados. Cada proyecto exige analizar el problema, diseñar las
clases, escoger estructuras de datos, manejar errores y construir una aplicación funcional.

## Proyectos

1. **Gestor de tareas** — listas, prioridades, excepciones y persistencia básica.
2. **Sistema de turnos** — cola y prioridades.
3. **Historial de navegación** — pila.
4. **Agenda de contactos** — POO + HashMap.
5. **Sistema de inventario** — colecciones + búsqueda + ordenamiento.
6. **Gestor de biblioteca** — libros, usuarios, préstamos y excepciones.
7. **Sistema de rutas** — grafos + BFS/DFS.
8. **Árbol de categorías** — BST + recorridos.
9. **Sistema de reservas** — POO + colecciones + validaciones.
10. **Proyecto integrador final** — combinar varias estructuras y algoritmos.

## Proyecto final

La meta es construir una aplicación desde cero siguiendo:

**requerimientos → casos de uso → modelo de clases → estructuras de datos → implementación →
pruebas → documentación → Git.**

No se debe usar una estructura solo porque aparece en el temario. Hay que justificar por qué se
elige una pila, cola, lista, mapa, árbol o grafo.
