# Proyecto final — Proyecto integrador final

## Enfoque
combinar varias estructuras y algoritmos.

## Objetivo
Diseñe y construya, a partir de un problema real que usted elija (por ejemplo un sistema de gestión de un pequeño negocio), una aplicación que combine al menos: una jerarquía de clases con herencia y polimorfismo, dos o más colecciones distintas (lista, mapa, conjunto), una estructura de pila o cola donde tenga sentido, manejo de excepciones propias, y al menos un algoritmo de ordenamiento o búsqueda implementado por usted mismo (no solo usando Collections.sort).

## Requisitos mínimos
1. Modele las clases necesarias siguiendo POO (encapsulación, y herencia/polimorfismo si aplica).
2. Elija las estructuras de datos adecuadas (lista, mapa, conjunto, pila, cola, árbol o grafo)
   justificando por qué se eligió cada una.
3. Valide los datos de entrada y maneje los errores esperables con excepciones propias.
4. Pruebe la aplicación con al menos 3 escenarios distintos, incluyendo casos límite o inválidos.

## Entregables
- Código fuente en `src/` de esta carpeta.
- Este README actualizado con: diseño de clases (puede ser un diagrama simple en texto), decisiones
  de diseño tomadas y cómo probó la aplicación.

## Proceso sugerido
**requerimientos → casos de uso → modelo de clases → estructuras de datos → implementación →
pruebas → documentación → commit.**

> Este proyecto integra varios temas vistos en las etapas anteriores del repositorio. No hay una
> única solución correcta: lo importante es justificar las decisiones de diseño tomadas.
